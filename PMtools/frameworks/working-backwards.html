Working Backwards (PR/FAQ)

Start from a press release and FAQ for the finished product to force clarity before building.

When to use

  • 0→1 products
  • Forcing customer-obsessed clarity

When not to use

  • Tiny incremental changes

Inputs

  • A crisp customer problem

Steps

  • Write the launch press release first
  • Write the customer + stakeholder FAQ
  • Only build if the PR is compelling

Outputs

  • A PR/FAQ doc
  • A go/no-go signal

Common mistakes

  • Writing it after deciding to build
  • Internal jargon in the PR

Example

Amazon famously requires a PR/FAQ before greenlighting new products.
